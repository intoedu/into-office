# 인투오피스 카카오 알림톡 템플릿 4종 (등록용 최종본)

솔라피 콘솔 → 카카오 → 알림톡 템플릿에 **그대로 붙여 넣어** 심사를 신청하는 문구입니다.

> 🔴 **변수 이름은 코드(`supabase/functions/_shared/alimtalk.ts`)와 한 글자도 다르면 안 됩니다.**
> 다르면 심사는 통과해도 발송이 실패합니다. 문구를 고치려면 코드도 같이 고쳐야 합니다.
> (2026-10-15 코드와 대조 완료)

## 2026-10-15 실제 등록 형태: 강조표기형

솔라피에는 **강조표기형**으로 등록합니다. 아래 각 템플릿의 본문 첫 줄 `[인투오피스] …` 은
강조표기 제목·보조문구로 옮기고 **본문에서는 뺍니다.** 변수 이름과 버튼은 그대로라 코드 변경은 없습니다.

| 템플릿 | 강조표기 보조문구 | 강조표기 제목 |
|---|---|---|
| 서명요청 | `인투오피스 전자서명` | `서명 요청이 도착했습니다` |
| 서명리마인드 | `인투오피스 전자서명` | `서명을 기다리고 있습니다` |
| 서명완료 | `인투오피스 전자서명` | `모든 서명이 완료되었습니다` |
| 가입승인 | `인투오피스` | `가입이 승인되었습니다` |

제목·보조문구에는 변수를 쓰지 않습니다 (코드가 따로 값을 보내지 않아도 되도록).

## 심사 통과를 위한 원칙

- 수신자의 행동(서명 요청 받음, 서명 완료, 가입 승인)에 따라 발송되는 **정보성** 안내입니다
- "이벤트", "할인", "무료", "지금 신청" 같은 **광고성 표현을 쓰지 않았습니다**
- 변수는 `#{변수명}` 형식입니다
- 버튼 링크는 **https:// 와 도메인을 고정**하고 뒤의 토큰만 변수로 둡니다
  (솔라피 안내: 변수 URL 은 프로토콜 영역을 고정해야 하고 100자까지 가능)
- 버튼은 **모바일 링크와 PC 링크를 둘 다** 넣으세요. PC 링크가 없으면 PC 카카오톡에서 버튼이 보이지 않습니다
- 본문에도 링크 줄(`#{서명링크}`)을 넣었습니다. 카카오톡이 없는 사람에게 문자로 대신 갈 때 버튼이 빠지기 때문입니다

## 1. 서명 요청

| 항목 | 값 |
|---|---|
| 템플릿명 | `인투오피스_서명요청` |
| 카테고리 | 서비스이용 > 이용안내/공지 (콘솔에서 가장 가까운 항목) |
| 환경변수 | `ALIMTALK_TPL_REQUEST` ← 승인 후 받은 템플릿 ID |

```
#{이름}님, 서명하실 문서가 도착했습니다.

[문서 정보]
- 문서: #{문서명}
- 보낸 곳: #{요청자}
- 기한: #{기한}까지

[함께 서명하는 분]
#{서명자목록}

아래 「서명하러 가기」를 누르면 문서 확인부터 서명까지 휴대폰에서 바로 진행됩니다.
링크: #{서명링크}

※ 본 전자서명은 「전자서명법」 제3조에 따라 서면 서명과 같은 효력을 가집니다.
```

| 버튼 | 유형 | 버튼명 | 모바일 / PC 링크 |
|---|---|---|---|
| 1 | 웹링크 | `서명하러 가기` | `https://intoedu.github.io/into-office/?s=#{서명토큰}` |

| 변수 | 예시 |
|---|---|
| `#{이름}` | 홍길동 |
| `#{요청자}` | 인투학원 |
| `#{문서명}` | 2026년 재학생 개인정보 동의서 |
| `#{기한}` | 2026년 10월 20일 오후 6:00 |
| `#{서명자목록}` | · 홍길동 님 (끝자리 1234) ⏎ · 김철수 님 (끝자리 5678) — 서명자 전원, 줄바꿈으로 구분 |
| `#{서명링크}` | https://intoedu.github.io/into-office/?s=3f9a…(48자) |
| `#{서명토큰}` | 3f9a…(48자) |

> 접근 암호를 설정한 문서라면 암호는 **이 메시지에 담지 마시고** 전화나 별도 문자로 전달하세요.

## 승인 후 Supabase 에 넣을 값

Supabase → Edge Functions → Secrets (Manage secrets)

| 이름 | 값 | 어디서 |
|---|---|---|
| `SOLAPI_API_KEY` | API Key | 솔라피 → 개발/연동 → API Key 관리 |
| `SOLAPI_API_SECRET` | API Secret | 〃 (발급 때 한 번만 보임) |
| `SOLAPI_PFID` | 발신프로필 ID (`KA01PF…`) | 솔라피 → 카카오 → 채널(발신프로필) |
| `SOLAPI_SENDER` | 등록한 발신번호 (숫자만) | 솔라피 → 발신번호 관리 |
| `ALIMTALK_TPL_REQUEST` | 템플릿 ID (`KA01TP…`) | 솔라피 → 템플릿 목록 |
| `ALIMTALK_TPL_REMIND` | 〃 | 〃 |
| `ALIMTALK_TPL_DONE` | 〃 | 〃 |
| `ALIMTALK_TPL_APPROVE` | 〃 | 〃 |

- 넣는 순간부터 발송이 시작됩니다. 배포를 다시 할 필요는 없습니다
- 템플릿 4개가 한꺼번에 승인되지 않아도 됩니다. **값이 들어간 종류만 발송**되고, 나머지는 기록만 남습니다
- 🔴 서비스 주소를 자체 도메인으로 바꾸면 **버튼 링크가 박힌 템플릿 4종을 전부 재심사**해야 합니다.
  주소를 바꿀 계획이 있다면 등록 전에 정하세요

## 발송 시점 (2026-10-15 코드 기준)

| 템플릿 | 발송 시점 | 코드 위치 |
|---|---|---|
| 서명 요청 | 문서 생성 · 대량 발송 직후 | `index.html` → `sendAlimtalk('request')` |
| 서명 리마인드 | 관리자가 리마인드를 보낼 때 | `index.html` → `sendAlimtalk('remind')` |
| 서명 완료 | 마지막 서명자가 서명한 직후 | `esign-sign` Edge Function (서버에서 자동) |
| 가입 승인 | 관리자가 승인 대기 회원을 승인할 때 | `index.html` → `sendApproveAlimtalk()` |

발송 결과는 `esign.alimtalk_logs` 에 남습니다 (`sent` / `failed` / `skipped`).
