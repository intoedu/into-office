# 인투오피스 데이터 보관 · 삭제 정책 (구현 문서)

고객 문서를 언제까지 보관하고 언제 지우는지를 **코드와 스케줄러로 강제**하는 체계입니다.
약관에 적어 두기만 하고 실제로는 안 지우는 상태를 만들지 않기 위한 구현입니다.

---

## 1. 정책 요약

| 조직 상태 | 문서 처리 |
|---|---|
| **구독 중** (`active`) | 기간 제한 없이 보관 |
| **무료 체험 중** (`trial`) | 보관 |
| **체험 만료** | 유예 시작 → **31일 후 영구 삭제** |
| **미납 30일 경과** (`past_due`) | 유예 시작 → **31일 후 영구 삭제** |
| **해지** (`terminated`) | 유예 시작 → **31일 후 영구 삭제** |
| **유예 중 재결제** | 삭제 예약 취소, 문서 그대로 복구 |

> 삭제 기준은 **서명 시점이 아니라 이용계약이 끝난 시점**입니다.
> 서명 후 일정 기간이 지나면 지우는 방식은 "5년 보관"이라는 서비스 가치와 정면으로 충돌합니다.

**유예 기간을 31일로 잡은 이유** — 약관상 "해지 후 30일"을 보장하려면 경계일 처리에 하루 여유가 필요합니다. `date_trunc('day', now()) + 31일`로 계산하므로 어느 시각에 해지해도 최소 30일이 확보됩니다.

---

## 2. 안내 발송 시점

유예가 시작되면 안내 일정이 자동으로 예약됩니다.

| 시점 | 내용 |
|---|---|
| 유예 시작 즉시 | 삭제 예정일 고지 + 전체 다운로드 안내 |
| 삭제 7일 전 | 재안내 |
| 삭제 1일 전 | 최종 안내 |

배치가 도래한 안내에 `executed_at`을 기록하면, 알림톡 발송 Edge Function이 이를 읽어 실제 메시지를 보냅니다. (발송 연동은 B8에서 붙습니다.)

---

## 3. 테이블

| 테이블 | 역할 |
|---|---|
| `esign.organizations` | `purge_at` — 이 시각 이후 소속 문서 영구 삭제. `purged_at` — 실제 삭제 완료 시각 |
| `esign.documents` | `org_id` 소속 조직, `purge_at` 개별 문서 삭제 예정 |
| `esign.retention_events` | 유예 시작 · 안내 예약 · 삭제 실행 이력 |
| `esign.purge_log` | 삭제된 문서의 **감사 기록**. 제목은 SHA-256 해시로만 남기고 원문은 남기지 않음 |

`purge_log`에 `file_path` · `signed_path`를 남기는 이유는 **스토리지 파일 정리** 때문입니다. DB 행은 삭제해도 Storage 버킷의 PDF는 남으므로, 정리 작업이 이 목록을 읽어 파일을 지운 뒤 `storage_cleared_at`을 기록합니다.

---

## 4. 실행 구조

```
pg_cron  매일 18:20 UTC (03:20 KST)
   └─ esign.retention_tick()
        ├─ 체험 만료 조직 → retention_begin_grace()
        ├─ 미납 30일 경과 → retention_begin_grace()
        ├─ 도래한 안내에 executed_at 기록
        └─ purge_at 도달 조직
             ├─ purge_log 에 감사 기록 이관
             ├─ documents 삭제 (signers · fields · signatures ·
             │                   audit_logs · reminders 는 CASCADE)
             └─ organizations.purged_at 기록
```

**함수**

| 함수 | 용도 |
|---|---|
| `esign.retention_begin_grace(org, reason)` | 유예 시작. 조직·문서에 `purge_at` 설정, 안내 3건 예약 |
| `esign.retention_cancel(org, note)` | 유예 취소. 재결제 시 문서 복구 |
| `esign.retention_tick()` | 일 1회 배치 |

세 함수 모두 `SECURITY DEFINER`이며 `anon` · `authenticated` 권한을 회수했습니다. 클라이언트에서 직접 호출할 수 없습니다.

---

## 5. 검증 결과

임시 조직으로 전 구간을 실행해 확인했습니다.

| 단계 | 결과 |
|---|---|
| 체험 만료 → 유예 | 조직 `terminated`, 삭제 예정일 설정, 문서에도 예정일 표시, 안내 3건 예약 |
| 재결제 → 복구 | 조직 `active`, 삭제 예정 해제, 문서 보존 확인 |
| 유예 종료 → 삭제 | 문서 0건 · 서명자 0건, 감사 기록 1건 생성, `purged_at` 기록 |
| 기존 데이터 | 1조직 · 8문서 그대로 유지 |

---

## 6. 아직 남은 것

- **스토리지 파일 정리** — `purge_log`에서 `storage_cleared_at is null`인 행을 읽어 Storage 객체를 삭제하는 Edge Function. DB 행만 지운 상태로는 PDF가 버킷에 남습니다.
- **안내 실제 발송** — 알림톡 연동(B8) 후 `retention_events`를 읽어 발송
- **다운로드 일괄 내려받기** — 유예 기간 중 전체 문서를 ZIP으로 받는 기능
- **사용자 화면** — 남은 일수와 다운로드 안내를 보여주는 배너

## 7. 함께 적용된 멀티테넌시 기반

보관 정책은 조직 단위로 동작하므로 아래가 함께 들어갔습니다.

| 테이블 | 내용 |
|---|---|
| `esign.plans` | 요금제 4종 (무료 체험 / 스탠다드 / 팀 / 비즈니스) |
| `esign.organizations` | 조직(테넌트) |
| `esign.memberships` | 사용자-조직 소속 및 권한 (owner / admin / member) |
| `esign.subscriptions` | 구독 기간 |
| `esign.payments` | 결제. `method` 에 `transfer`(계좌이체)와 `card`를 함께 두어 PG 전환 시 재작업이 없도록 설계 |
| `esign.usage_counters` | 기간별 문서 · 알림톡 사용량 |

**기존 코드를 건드리지 않았습니다.** 신규 컬럼은 모두 nullable이고, 조직 자동 귀속과 사용량 집계는 트리거로 처리하므로 기존 RPC가 그대로 동작합니다.

| 트리거 | 동작 |
|---|---|
| `trg_fill_document_org` (BEFORE INSERT) | `org_id`가 비어 있으면 작성자의 소속 조직으로 채움 |
| `trg_count_document_usage` (AFTER INSERT) | 해당 기간 사용량 +1 |

**신규 RPC**

| 함수 | 용도 |
|---|---|
| `esign_my_org()` | 내 조직 · 요금제 · 사용량 · 보관 상태 |
| `esign_admin_orgs()` | 플랫폼 관리자용 조직 목록 |
| `esign_admin_payments(status)` | 입금 대기 목록 |
| `esign_admin_confirm_payment(id, plan, cycle)` | 입금 확인 → 구독 활성화 (유예 중이면 자동 복구) |
| `esign_admin_terminate_org(id, reason)` | 해지 → 유예 시작 |
| `esign_admin_reactivate_org(id)` | 복구 |

기존 데이터는 `인투마케팅` 조직으로 귀속했습니다 (회원 3명, 문서 8건).
