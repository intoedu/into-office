# 구글 로그인 설정 가이드

인투오피스에 구글 로그인을 붙이기 위한 콘솔 설정 절차입니다.
**앱 코드는 이미 완성되어 배포되어 있습니다.** 아래는 전부 웹 콘솔에서
클릭으로 하는 작업이며, 코드를 건드릴 일은 없습니다.

---

## 미리 복사해 둘 값 3개

작업 중 이 세 값을 붙여넣게 됩니다. 메모장에 미리 옮겨 두면 편합니다.

| 이름 | 값 |
|---|---|
| **① 승인된 리디렉션 URI** (구글에 입력) | `https://lplektkqodrncigysfan.supabase.co/auth/v1/callback` |
| **② 승인된 자바스크립트 원본** (구글에 입력) | `https://intoedu.github.io` |
| **③ 사이트 주소** (Supabase에 입력) | `https://intoedu.github.io/into-office/` |

①은 Supabase 프로젝트 주소 뒤에 `/auth/v1/callback` 을 붙인 것입니다.
구글은 로그인 성공 후 사용자를 **Supabase로** 먼저 돌려보내고,
Supabase가 다시 우리 사이트로 보냅니다. 그래서 구글에 등록하는 주소는
우리 사이트가 아니라 Supabase 주소입니다. 여기서 가장 많이 틀립니다.

약관·방침 주소도 필요합니다.

| 이름 | 값 |
|---|---|
| 앱 홈페이지 | `https://intoedu.github.io/into-office/` |
| 개인정보처리방침 | `https://intoedu.github.io/into-office/?legal=privacy` |
| 서비스 약관 | `https://intoedu.github.io/into-office/?legal=terms` |

## 1단계 — 구글 클라우드 프로젝트 만들기

1. <https://console.cloud.google.com> 접속 (인투오피스 운영용 구글 계정으로 로그인)
2. 화면 상단 왼쪽의 **프로젝트 선택** 드롭다운 클릭
3. **새 프로젝트** → 이름 `into-office` → **만들기**
4. 만들어진 뒤 상단 드롭다운에서 그 프로젝트가 선택되어 있는지 확인

> 결제 카드 등록은 필요 없습니다. 구글 로그인 기능 자체는 무료입니다.

---

## 2단계 — OAuth 동의 화면 설정

로그인 버튼을 눌렀을 때 사용자에게 보이는 **"인투오피스가 내 계정에 접근하려 합니다"**
화면을 만드는 단계입니다.

1. 왼쪽 메뉴 **API 및 서비스** → **OAuth 동의 화면**
   (최근 콘솔에서는 **Google 인증 플랫폼**으로 이름이 바뀌었고,
   **브랜딩 / 대상 / 클라이언트** 세 탭으로 나뉘어 있습니다)
2. **시작하기** 클릭
3. 앱 이름: `인투오피스`
4. 사용자 지원 이메일: `intoffice1@gmail.com`
5. **대상(Audience)** — ⚠️ 반드시 **외부(External)** 선택
6. 개발자 연락처 이메일: `intoffice1@gmail.com`
7. 저장

> ⚠️ **여기가 가장 중요합니다.**
> **내부(Internal)** 를 고르면 같은 조직 구성원만 로그인할 수 있어
> 외부 고객이 전혀 쓰지 못합니다. 나중에 바꾸기 어려우니 반드시 **외부**입니다.

### 브랜딩 탭 (홈페이지·방침 주소)

같은 화면의 **브랜딩** 탭에서 위 표의 홈페이지 / 개인정보처리방침 /
서비스 약관 주소를 넣습니다.

---

## 3단계 — OAuth 클라이언트 ID 만들기

1. 왼쪽 메뉴 **API 및 서비스** → **사용자 인증 정보(Credentials)**
2. 상단 **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
3. 애플리케이션 유형: **웹 애플리케이션**
4. 이름: `인투오피스 웹`
5. **승인된 자바스크립트 원본** → URI 추가 → **②** `https://intoedu.github.io`
6. **승인된 리디렉션 URI** → URI 추가 → **①**
   `https://lplektkqodrncigysfan.supabase.co/auth/v1/callback`
7. **만들기**
8. 팝업에 뜨는 **클라이언트 ID** 와 **클라이언트 보안 비밀번호(Secret)** 를
   메모장에 복사

> Secret은 이 팝업을 닫으면 다시 보기 어려울 수 있습니다. 반드시 지금 복사하세요.
> 이 두 값은 비밀번호와 같습니다. 코드나 문서에 적어 두지 마세요.

---

## 4단계 — Supabase에 붙여넣기

1. <https://supabase.com/dashboard> 접속 → 프로젝트 선택
2. 왼쪽 **Authentication** → **Sign In / Providers**
3. 목록에서 **Google** 을 찾아 클릭 → **Enable Sign in with Google** 켜기
4. **Client ID** 칸에 3단계에서 복사한 클라이언트 ID 붙여넣기
5. **Client Secret** 칸에 Secret 붙여넣기
6. **Save**

---

## 5단계 — Supabase 돌아올 주소 등록

로그인이 끝난 뒤 사용자를 우리 사이트로 돌려보내려면
그 주소가 허용 목록에 있어야 합니다.

1. **Authentication** → **URL Configuration**
2. **Site URL**: `https://intoedu.github.io/into-office/`
3. **Redirect URLs** 에도 같은 주소 추가
4. 저장

> 이 단계를 빠뜨리면 로그인은 되는데 마지막에 엉뚱한 곳으로 튕깁니다.

---

## 6단계 — 실제로 테스트

1. **시크릿 창(새 사생활 보호 창)** 으로 <https://intoedu.github.io/into-office/> 접속
2. 화면 아래 **BUILD** 표시가 최신인지 확인 (아니면 새로고침)
3. **구글 계정으로 계속하기** 클릭
4. 구글 계정 선택 화면 → 계정 선택
5. **가입 화면으로 넘어가야 정상입니다.** 바로 대시보드로 들어가면 안 됩니다.
   - 이메일·비밀번호 칸은 숨겨져 있고
   - 아이디 · 이름 · 출생년도 · 연락처 · 개인정보 동의를 받습니다
   - 이름 칸에는 구글 계정 이름이 미리 채워집니다
6. **가입 완료** 를 누르면 그때 대시보드로 들어갑니다
7. 로그아웃 후 다시 구글 로그인 → 이번에는 가입 화면 없이 바로 들어가야 합니다

---

## 7단계 — 게시(Production) 전환 ⚠️ 판매 전 필수

**테스트 상태로 두면 등록한 테스트 사용자 100명까지만 로그인됩니다.**
외부 고객에게 판매하려면 반드시 게시해야 합니다.

1. **API 및 서비스** → **OAuth 동의 화면**(Google 인증 플랫폼) → **대상(Audience)**
2. **앱 게시(Publish App)** 클릭 → 확인

인투오피스는 이메일·프로필 같은 기본 정보만 요청하므로
**구글의 별도 심사 없이 바로 게시됩니다.**
(구글 드라이브·지메일 같은 민감 권한을 요청할 때만 2~6주 심사가 붙습니다.
지금 앱은 그런 권한을 쓰지 않습니다.)

## 자주 막히는 지점

| 증상 | 원인 | 해결 |
|---|---|---|
| `redirect_uri_mismatch` | 3단계 리디렉션 URI 오타 | `https://lplektkqodrncigysfan.supabase.co/auth/v1/callback` 정확히 일치 확인 (끝 슬래시 없음) |
| `구글 로그인이 아직 설정되지 않았습니다` | Supabase에서 Google 미활성화 | 4단계 다시 확인 |
| 로그인 후 엉뚱한 페이지 | Redirect URLs 누락 | 5단계 확인 |
| 로그인은 되는데 바로 대시보드 진입 | 이미 가입된 계정 | 정상 동작 |
| 이 앱은 확인되지 않았습니다 경고 | 미게시 상태 | 7단계 게시 |
| 고객이 로그인 안 됨 | 100명 제한 또는 내부(Internal) 설정 | 2단계 대상 = 외부인지 확인 후 7단계 게시 |

## 확인하지 못한 부분

- 구글 콘솔 UI는 자주 바뀝니다. 메뉴 이름이 문서와 다를 수 있습니다
  (예: `OAuth 동의 화면` → `Google 인증 플랫폼`).
  이름이 달라도 **브랜딩 / 대상 / 클라이언트** 세 항목을 찾으면 같은 화면입니다.
- 브랜딩 탭의 **승인된 도메인**에 `intoedu.github.io` 를 넣어야 할 수 있는데,
  `github.io` 는 공용 도메인이라 구글이 거부할 가능성이 있습니다.
  거부되면 홈페이지·방침 주소 입력을 건너뛰고 진행해도 로그인 기능 자체는 동작합니다.
  자체 도메인을 구입하면 이 문제는 사라집니다.
- 이 환경에서는 구글 콘솔과 실제 사이트에 접속할 수 없어
  위 절차를 직접 실행해 확인하지는 못했습니다.
