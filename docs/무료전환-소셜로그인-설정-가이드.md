# 무료 플랜 전환 · 구글/카카오 로그인 설정 가이드

인투오피스 Supabase 프로젝트(`lplektkqodrncigysfan`)를 무료(Free) 조직으로 옮기고,
구글·카카오 로그인을 켜기 위한 대시보드 작업 순서입니다.

코드(`index.html`)와 DB 쪽 준비는 끝나 있습니다. 아래는 **대시보드에서 사람이 직접 해야 하는 작업**입니다.

| 순서 | 작업 | 소요 |
|---|---|---|
| 1 | Supabase 프로젝트를 무료 조직으로 이전 | 5분 |
| 2 | Supabase URL 설정 확인 | 2분 |
| 3 | 구글 OAuth 클라이언트 발급 → Supabase 등록 | 15분 |
| 4 | 카카오 로그인 앱 설정 → Supabase 등록 | 20분 (+비즈 앱 전환 심사) |
| 5 | 동작 확인 | 10분 |

---

## 1. 프로젝트를 무료 조직으로 이전

새로 복사하지 않고 **기존 프로젝트를 그대로 옮깁니다.** DB, 사용자, 파일, Edge Function, 예약 작업,
주소(URL), 키가 모두 유지되므로 앱 코드를 바꿀 필요가 없습니다.
(공식 문서: https://supabase.com/docs/guides/platform/project-transfer)

```
[ ] https://supabase.com/dashboard/project/lplektkqodrncigysfan/settings/general
[ ] Transfer project → 대상: 새로 만든 무료 조직 → Transfer
```

- 유료 → 무료 이전 시 **1~2분 접속 끊김**이 있을 수 있습니다. 사용자가 적은 시간에 하세요.
- 이전 조건: GitHub 연동(Integrations → GitHub)과 로그 드레인이 없어야 합니다. 막히면 먼저 해제하세요.
- 무료 플랜은 계정당 **활성 무료 프로젝트 2개**까지입니다.

### 무료 플랜에서 달라지는 점

| 항목 | 무료 플랜 | 인투오피스 현재 사용량 (2026-10-15) | 대응 |
|---|---|---|---|
| DB 용량 | 500MB | 약 36MB | 여유 있음 |
| 파일 저장 | 1GB | 약 108MB (그중 97MB는 사용하지 않는 `materials` 버킷) | 여유 있음. `materials` 정리 시 더 여유 |
| 월 활성 사용자 | 50,000명 | 5명 | 여유 있음 |
| 데이터 전송 | 5GB/월 | — | 대시보드 Usage 에서 월 1회 확인 |
| **일시정지** | 활동이 없으면 일시정지 | — | 아래 "자동 정지 예방" 참고 |
| **자동 백업** | 없음 | — | 아래 "백업" 참고 |

**자동 정지 예방**: `.github/workflows/supabase-keepalive.yml` 이 이틀에 한 번 가벼운 DB 조회를 보냅니다.
GitHub 저장소의 Actions 탭에서 이 워크플로가 켜져 있는지 확인하세요. 혹시 정지되더라도
대시보드에서 **Restore** 를 누르면 데이터 손실 없이 다시 켜집니다.
(어떤 요청이 '활동'으로 인정되는지는 Supabase 가 공개한 기준을 직접 확인하지 못했습니다.
정지 알림 메일이 오면 바로 Restore 하세요.)

**백업**: 무료 플랜은 자동 백업이 없습니다. 월 1회 이상 Supabase CLI 로 백업 파일을 받아 두세요.

```
supabase db dump --db-url "<Project Settings → Database 의 연결 문자열>" -f backup_YYYYMMDD.sql
supabase db dump --db-url "<같은 연결 문자열>" --data-only -f data_YYYYMMDD.sql
```

**인증 메일**: Supabase 기본 메일 발송은 시간당 발송 수 제한이 매우 낮습니다. 비밀번호 재설정 메일이
자주 필요하면 Authentication → Emails → SMTP Settings 에 자체 SMTP(예: Gmail, 네이버 웍스)를 등록하세요.

## 4. 카카오 로그인

### 4-1. 카카오 디벨로퍼스

카카오톡 공유에 쓰는 기존 앱(JavaScript 키 `5b91…9324`)을 그대로 써도 되고, 새 앱을 만들어도 됩니다.

```
[ ] https://developers.kakao.com → 내 애플리케이션 → 앱 선택
[ ] 앱 설정 → 플랫폼 키 → REST API 키 확인 (= Supabase 의 Client ID)
[ ] REST API 키 상세 → 카카오 로그인 Redirect URI 등록
      https://lplektkqodrncigysfan.supabase.co/auth/v1/callback
[ ] REST API 키 상세 → 카카오 로그인 Client Secret 코드 확인 + 활성화 (= Supabase 의 Client Secret)
[ ] 제품 설정 → 카카오 로그인 → 사용 설정 ON
[ ] 제품 설정 → 카카오 로그인 → 동의항목
      닉네임(profile_nickname)         필수 동의
      프로필 사진(profile_image)        선택 동의
      카카오계정 이메일(account_email)   필수 또는 선택 동의 ← 비즈 앱만 가능
```

메뉴 이름은 카카오 디벨로퍼스 개편에 따라 조금 다를 수 있습니다.

### 4-2. 이메일 동의항목과 비즈 앱 (중요)

카카오는 **비즈 앱으로 전환한 앱에만 이메일을 줍니다.**
인투마케팅 사업자등록번호(306-24-53380)로 비즈 앱 전환을 신청하는 것을 권합니다.

```
[ ] 앱 설정 → 앱 → 일반 → 비즈니스 정보 입력 (사업자 정보 등록) → 비즈 앱 전환
[ ] 전환 후 동의항목에서 카카오계정(이메일) 사용 설정
```

#### 비즈 앱 심사 대비 (2026-10-15 준비 완료)

카카오 데브톡의 반려 사례를 보면, 심사는 **실제 서비스 화면에 신청한 사업자 정보가 「운영 주체」로
보이는지**, 그리고 **사업자등록증과 상호 · 번호가 정확히 일치하는지**를 봅니다.
별도 소개 페이지만 만들어서는 통과하지 못한 사례가 있어, 실제 서비스 화면에 넣었습니다.
(공식 정책 문서가 아니라 개발자 문의 게시판의 답변을 근거로 했습니다.)

| 위치 | 들어간 내용 |
|---|---|
| 첫 화면 푸터 | 운영 주체 · 상호 · 대표자 · 사업자등록번호(+사업자정보확인) · 통신판매업 신고번호 · 주소 · 전화 · 이메일 · 카카오 채널 · 운영사 홈페이지 |
| 로그인 화면 아래 | 위와 같은 정보 + 약관 · 개인정보처리방침 · 환불규정 링크 |
| 이용약관 · 개인정보처리방침 · 환불규정 | 문서 끝에 **사업자 정보 표** |
| intomarketing.co.kr 푸터 | 「운영 서비스 : 인투오피스」 링크 (`intoedu/intomarketing` 저장소) |

약관 바로가기 주소 (심사 신청서에 적을 때 사용)

```
이용약관          https://intoedu.github.io/into-office/?legal=terms
개인정보처리방침   https://intoedu.github.io/into-office/?legal=privacy
환불규정          https://intoedu.github.io/into-office/?legal=refund
```

신청 전 확인

```
[ ] 두 저장소의 작업 브랜치를 main 에 병합 → 실제 사이트에 반영됐는지 시크릿 창으로 확인
[ ] 디벨로퍼스 비즈니스 정보: 사업자등록번호 306-24-53380 · 상호 「인투마케팅」 (등록증과 한 글자도 다르지 않게)
[ ] 사업자등록증 이미지 첨부
[ ] 서비스 URL: https://intoedu.github.io/into-office/
[ ] (권장) 통신판매업 신고에 인투오피스 주소(intoedu.github.io/into-office)를 인터넷 도메인으로 추가 — 변경신고
[ ] (권장) 홈택스 업종에 「응용 소프트웨어 개발 및 공급업」 추가 — 현재 종목은 광고·디자인·미디어콘텐츠
```

| | 비즈 앱 (이메일 받음) | 일반 앱 (이메일 없음) |
|---|---|---|
| 카카오로 가입·로그인 | 가능 | 가능 |
| 같은 이메일의 기존 계정과 자동 연결 | 가능 | 불가 (별도 계정이 됨) |
| 관리자의 비밀번호 재설정 링크 발급 | 해당 없음 (소셜 계정) | 해당 없음 |
| Supabase 추가 설정 | 없음 | **Allow users without an email** 켜기 |

DB 는 이메일이 없는 카카오 사용자도 가입되도록 이미 수정해 두었습니다
(`supabase/migrations/20261015022400_oauth_users_without_email.sql`).

### 4-3. Supabase 에 등록

```
[ ] Authentication → Sign In / Providers → Kakao → Enable
[ ] Kakao Client ID: REST API 키 / Kakao Client Secret: Client Secret 코드
[ ] (비즈 앱이 아닌 경우만) Allow users without an email → ON
[ ] Save
```

## 5. 동작 확인

```
[ ] 시크릿 창에서 https://intoedu.github.io/into-office/ 접속
[ ] 화면 하단 버전이 v2026-10-15.1 인지 확인 (아니면 새로고침)
[ ] "구글 계정으로 계속하기" → 계정 선택 → 가입 정보 입력 화면이 나오는지
[ ] "카카오로 계속하기" → 동의 → 가입 정보 입력 화면이 나오는지
[ ] 가입 완료 → "승인 대기" 화면 → 관리자 계정으로 회원 승인 → 다시 로그인
[ ] 기존 아이디/비밀번호 로그인도 그대로 되는지
[ ] 카카오톡 안에서 링크를 열고 구글 버튼을 누르면 외부 브라우저로 넘어가는지
```

### 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| "구글(카카오) 로그인이 아직 설정되지 않았습니다" | Supabase 에서 Provider 가 꺼져 있음 | 3-2 / 4-3 |
| 구글 화면에 `redirect_uri_mismatch` | 구글 콘솔의 리디렉션 URI 오타 | 3-1 의 URI 를 그대로 복사 |
| 카카오 화면에 `KOE006` | 카카오의 Redirect URI 미등록 | 4-1 |
| 카카오 화면에 `KOE205` | 동의항목 미설정 | 4-1 동의항목 |
| 로그인 후 다른 주소로 감 / 로그인 화면으로 돌아옴 | Redirect URLs 미등록 | 2 |
| 구글 화면에 `403 disallowed_useragent` | 카카오톡 등 앱 내장 브라우저 | 크롬·사파리로 열기 (카카오톡은 자동 전환) |
| 카카오 로그인 후 "Database error saving new user" | 이메일 없는 사용자 처리 마이그레이션 누락 | 위 마이그레이션 적용 여부 확인 |
