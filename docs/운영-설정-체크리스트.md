## 3. 알림톡 발송 설정

발송 코드는 배포되어 있습니다(`esign-notify`). **키가 없는 동안에는 실제 발송 없이 기록만 남고**, 아래 값을 넣는 순간 발송이 시작됩니다.

Supabase 대시보드 → Edge Functions → Secrets

| 이름 | 값 |
|---|---|
| `SOLAPI_API_KEY` | 솔라피 API Key |
| `SOLAPI_API_SECRET` | 솔라피 API Secret |
| `SOLAPI_PFID` | 발신프로필 키 |
| `SOLAPI_SENDER` | 등록한 발신번호 |
| `ALIMTALK_TPL_REQUEST` | 서명요청 템플릿 코드 |
| `ALIMTALK_TPL_REMIND` | 리마인드 템플릿 코드 |
| `ALIMTALK_TPL_DONE` | 서명완료 템플릿 코드 |
| `SIGN_BASE_URL` | `https://intoedu.github.io/into-office/` |

### 템플릿에 변수가 하나 늘었습니다

멀티테넌시 도입으로 **`#{조직명}`** 이 추가됐습니다. 템플릿 심사 신청 전에 반영하세요.

```
[인투오피스] 전자서명 요청

#{이름}님, 안녕하세요.
#{조직명}의 #{요청자}님이 아래 문서에 대한 전자서명을 요청하였습니다.

▶ 문서명: #{문서명}
▶ 서명 기한: #{기한}
```

승인된 템플릿은 나중에 변수를 늘릴 수 없으므로 **반드시 등록 전에** 넣어야 합니다.

> ⚠️ 솔라피 API 규격(엔드포인트·인증 헤더·`kakaoOptions` 필드명)은 작업 환경에서
> solapi.com 접속이 차단되어 공식 문서와 대조하지 못했습니다.
> 첫 발송 전에 본인 번호로 테스트해 보시고, 실패하면 `esign.alimtalk_logs` 의
> `error` 컬럼에 원인이 남습니다.

## 4. 보관 배치 스케줄

| 작업 | 상태 |
|---|---|
| 유예 시작 · 영구 삭제 (DB) | ✅ `pg_cron` 이 매일 03:20(KST) 자동 실행 |
| 스토리지 파일 정리 · 안내 발송 | ⬜ **수동 설정 필요** |

스토리지 정리는 `esign-retention` Edge Function이 담당하는데, 아직 스케줄이 걸려 있지 않습니다.

```
[ ] Supabase 대시보드 → Integrations → Cron
[ ] 새 작업 생성: esign-retention 함수를 매일 1회 호출
    (권장 시각 03:40 KST = 18:40 UTC)
```

> 대시보드 Cron을 쓰지 않고 `pg_cron` 으로 직접 호출하려면 서비스 키를 DB에
> 저장해야 합니다. **키를 DB에 두는 것은 보안상 판단이 필요한 사안이라 제가
> 임의로 하지 않았습니다.** 대시보드 Cron 쪽이 안전합니다.

당장은 관리자 화면 `🏢 조직 · 입금` 탭의 **「보관 배치 지금 실행」** 버튼으로
DB 정리분을 수동 실행할 수 있고, 스토리지 정리 대기 건수도 같은 화면에 표시됩니다.

## 5. ⚠️ 반드시 검토하셔야 할 보안 사항

**`esign-docs` 스토리지 버킷이 public 으로 열려 있습니다.**

파일 경로만 알면 **로그인 없이 누구나 계약서 PDF를 내려받을 수 있습니다.** 경로가
추측하기 어렵더라도, 유료 전자서명 서비스에서 이 상태는 위험합니다. 링크가 한 번
유출되면 회수할 방법이 없습니다.

**바꾸지 않은 이유** — 버킷을 private으로 돌리면 현재 앱의 문서 열람·다운로드가
전부 깨집니다. Signed URL 방식으로 바꾸는 작업이 함께 필요합니다.

**권장 조치**
1. 버킷을 private 으로 전환
2. 문서 조회 시 서버에서 유효기간 있는 Signed URL 발급
3. 서명자 링크도 Signed URL 경유로 변경

**유료 고객을 받기 전에 처리하시기를 강하게 권합니다.** 지금은 내부 이용이라
당장의 피해는 없지만, 외부 고객 계약서가 들어오는 순간 성격이 달라집니다.

## 6. 입금 계좌

**계좌는 코드에 넣지 않았습니다.** 관리자 화면에서 직접 등록하시면 됩니다.

```
[ ] 로그인 → 🏢 조직 · 입금 탭 → 「입금 계좌 설정」
[ ] 은행 · 계좌번호 · 예금주 입력 후 저장
```

| | |
|---|---|
| 저장 위치 | `esign.app_settings` (DB) |
| 공개 페이지 노출 | **없음** |
| 보이는 사람 | 요금제를 신청한 **조직 소유자에게만** |
| 변경 시 | 배포 불필요, 저장 즉시 반영 |

계좌번호를 공개 페이지에 두면 사칭 사기에 악용될 수 있고, 계좌를 바꿀 때마다 배포가 필요해집니다. 그래서 설정값으로 분리했습니다.

### 계좌 명의는 인투마케팅으로 하시면 됩니다

**서비스명(인투오피스)과 사업자 상호(인투마케팅)가 달라도 아무 문제가 없습니다.**
전자상거래법이 요구하는 것은 사업자 정보의 **표시**이지 상호와 서비스명의 일치가 아닙니다.

- 비바리퍼블리카 → 토스
- 우아한형제들 → 배달의민족
- **인투마케팅 → 인투오피스**

홈페이지에 이미 *"인투오피스는 인투마케팅이 운영하는 전자서명 서비스입니다"* 라고 명시되어 있어 표시 의무를 충족합니다. 계좌와 세금계산서 모두 인투마케팅 명의로 발행하시면 됩니다.

통신판매업 신고서에도 상호는 사업자등록증대로(인투마케팅) 적고, **사이트명과 도메인은 별도 칸에 기재**하게 되어 있습니다. 제도 자체가 이 구조를 전제로 만들어져 있습니다.

**인투오피스 명의로 별도 사업자를 낼 필요가 없습니다.** 오히려 사업자가 2개가 되면 부가세 신고 2회, 종합소득세 2회, 카카오 비즈니스 인증 재실시, 통신판매업 신고 별도로 행정 부담만 배가 됩니다.

## 7. 통신판매업 신고

유료 판매를 시작하면 필요합니다. 인투마케팅은 **일반과세자**라 간이과세자 면제에
해당하지 않고, 월 구독은 거래횟수가 빨리 쌓입니다(고객 5명 × 12개월 = 60회).

```
[ ] 구매안전서비스 이용확인증 발급 (KB·NH농협·IBK기업·우체국)
[ ] 정부24 또는 유성구청에서 통신판매업 신고
```

첫해는 직전년도 거래가 없어 면제 대상이지만, **2년차에는 신고 대상**이 됩니다.
