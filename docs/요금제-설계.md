> 공식 가격 페이지를 직접 대조하지 못했으므로 계약 전 확인이 필요합니다.

## 2. 요금제

| 플랜 | 월 요금 | 문서 / 월 | 팀원 | 초과 단가 |
|---|---|---|---|---|
| **무료 체험** | 0원 | 10건 (가입 후 30일) | 1명 | 초과 불가 |
| **스탠다드** | **6,900원** | **30건** | 3명 | 건당 250원 |
| **팀** | 19,900원 | 120건 | 10명 | 건당 200원 |
| **비즈니스** | 49,900원 | 400건 | 무제한 | 건당 150원 |

- 표시 가격은 **VAT 포함**입니다 (스탠다드 공급가 6,273원 + VAT 627원)
- 연간 결제 시 **2개월분 무료** (16.7% 할인) — 현금흐름과 이탈 방지 양쪽에 유리
- 무료 체험은 카드 등록 없이 시작, 10건 소진 또는 30일 경과 시 자동 종료

### 초과분 단가를 250원으로 잡은 근거

원가 50원의 5배입니다. 그러면서 상위 플랜으로 자연스럽게 유도됩니다.

| 전환 지점 | 계산 | 결과 |
|---|---|---|
| 스탠다드 → 팀 | 6,900 + 250n = 19,900 | n = 52 → **총 82건**부터 팀이 유리 |
| 팀 → 비즈니스 | 19,900 + 200n = 49,900 | n = 150 → **총 270건**부터 비즈니스가 유리 |

초과 요금이 상위 플랜 가격을 넘기 직전에 업그레이드 안내를 띄우면 됩니다.

### 손익분기점

스탠다드 고객이 평균 18건(한도의 60%)을 쓴다고 가정합니다.

```
고객 1명당 공헌이익 = 6,273원 − (18건 × 50원) = 5,373원
손익분기 고객 수     = 38,000원 ÷ 5,373원 = 7.1명

→ 스탠다드 고객 8명이면 고정비를 넘습니다.
```

## 4. 반드시 짚어야 할 리스크

### (1) 5년 보관 의무가 스토리지를 영구히 누적시킵니다

현재 앱은 「전자문서 및 전자거래 기본법」에 따라 **계약 종료 후 5년 보관**을 명시하고 있습니다. 해지한 고객의 문서까지 계속 보관하면 스토리지가 한 방향으로만 쌓입니다.

```
고객 100명 × 월 18건 × 12개월 = 연 21,600건
21,600건 × 4MB = 연 86GB

→ Supabase Pro 기본 100GB를 1년 조금 넘겨 소진
→ 3년이면 260GB, 스토리지 추가 과금 발생
```

**대응책 (약관에 반드시 명시)**
- 해지 후 30일간 전체 문서 다운로드 기간 제공 → 이후 삭제
- 장기 보관이 필요한 고객에게는 **보관 연장을 유료 옵션**으로 제공
- 이 조항이 없으면 해지 고객의 원가를 영원히 떠안게 됩니다

### (2) 비영리·종교단체는 사용량이 계절을 탑니다

평소 0건이다가 특정 시기(신입 등록, 행사 동의서, 연간 서약)에 100건이 몰립니다. 월 단위 한도로는 그 달에만 초과 요금이 크게 나옵니다.

**대응책**
- 연간 결제(2개월 무료)를 기본 권장 — 연 단위로 보면 한도가 충분합니다
- 초과 단가를 낮게(250원) 유지해 한 달 몰림을 흡수
- 미사용분 이월(rollover)은 정산이 복잡해지므로 권하지 않습니다

### (3) 알림톡 원가가 요금제의 바닥을 정합니다

6,900원에서 알림톡 원가만으로 소진되는 지점은 **138건**입니다(6,900 ÷ 50원). 스탠다드 한도를 이보다 크게 잡으면 팔수록 손해입니다. 30건은 충분히 안전한 선입니다.

### (4) 무료 체험이 원가를 만듭니다

무료 10건 = 원가 500원입니다. 전환율 20%를 가정하면 유료 고객 1명을 얻는 데 체험 5명 = 2,500원이 듭니다. 스탠다드 한 달치(6,273원)로 회수되므로 감당 가능하지만, **체험 남용 방지**(사업자번호 또는 휴대폰 기준 1회 제한)가 필요합니다.

## 5. 결제 방식 — 계좌이체 수동 운영

### 가능합니다. 인투마케팅 사업자로 운영할 수 있습니다.

사업자등록증 하나로 여러 사업을 영위할 수 있습니다. 필요한 것은 **업종 추가**뿐입니다(정보통신업 / 응용 소프트웨어 개발 및 공급업).

### 계좌이체 방식의 장단점

| | 내용 |
|---|---|
| **장점** | PG 계약·심사 불필요 · 결제 수수료 0원 · 즉시 시작 가능 |
| | 현재 앱이 **이미 관리자 승인제**라 수동 흐름과 궁합이 맞음 |
| **단점** | 입금 확인 → 승인 → 세금계산서 발행이 전부 수동 |
| | 자동 갱신 불가 → 매달 재입금 안내 필요, 이탈률 상승 |
| | 고객 100명이면 매달 100건 입금 대조. 사람이 감당할 수 없는 지점이 옵니다 |

### 통신판매업 신고 — 첫해는 면제 가능, 2년차부터는 대상

면제 기준은 둘 중 하나입니다.

1. 「부가가치세법」상 **간이과세자** → 인투마케팅은 **일반과세자**이므로 해당 없음
2. **직전년도 통신판매 거래횟수 50회 미만** → 첫해는 직전년도 실적이 없으므로 해당

**주의할 점** — 월 구독은 거래횟수가 빠르게 쌓입니다.

```
고객 5명 × 12개월 = 연 60회  → 이미 50회 초과
```

즉 **고객이 5명만 넘어도 2년차에는 신고 대상**이 됩니다. 처음부터 신고를 준비하는 편이 안전합니다.

> 다만 월 구독의 "거래횟수"를 결제 건수로 볼지 계약 건수로 볼지는 제가 확정하지 못했습니다.
> 보수적으로 결제 건수로 보았습니다. 유성구청 지역경제과에 확인이 필요합니다.

### 계좌이체만 받아도 에스크로 확인증이 필요합니다

신고 시 **구매안전서비스 이용확인증**을 제출해야 합니다. 계좌이체·무통장입금처럼 대금을 먼저 받는 선지급식 거래가 대상이기 때문입니다. KB국민·NH농협·IBK기업은행·우체국에서 발급받을 수 있습니다.

### 권장 경로

```
0~30명    계좌이체 수동 + 관리자 승인      (현재 구조 그대로 활용)
30~50명   통신판매업 신고 + PG 계약 준비
50명~     PG 정기결제(빌링) 전환, 승인 자동화
```

계좌이체로 시작하는 것은 합리적입니다. 다만 **30명을 넘기면 수동 운영이 병목이 됩니다.** 그 시점에는 통신판매업 신고도 어차피 필요하므로, 두 가지를 함께 처리하면 됩니다.

## 6. 구현에 필요한 것

### DB (Phase 2 멀티테넌시와 함께)

```
organizations      id, name, biz_no, plan_id, status, trial_ends_at
memberships        org_id, user_id, role(owner/admin/member)
plans              code, name, price, doc_quota, seat_quota, overage_unit_price
subscriptions      org_id, plan_id, period_start, period_end, status, paid_at
usage_counters     org_id, period(YYYY-MM), doc_count, alimtalk_count
payments           org_id, amount, method(transfer/card), receipt_no, confirmed_by
```

`payments.method`에 `transfer`(계좌이체)를 두면, 나중에 PG를 붙일 때 `card`를 추가하는 것만으로 확장됩니다. **처음부터 두 방식을 모두 담을 수 있게 설계해야** 전환 시 재작업이 없습니다.

### 애플리케이션

- 문서 생성 시 한도 검사 → 초과 시 경고 또는 차단
- 사용량 대시보드 (이번 달 n / 30건)
- 한도 80% 도달 시 알림
- 관리자용 입금 확인 → 구독 활성화 화면
- 체험 종료 D-7 안내

### 문서 (유료화 필수)

- 이용약관 (보관·삭제 정책 포함)
- 개인정보처리방침
- 환불규정
