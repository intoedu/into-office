# 결제하면 바로 가입 승인 · 카드 결제(토스페이먼츠) 설정 가이드

2026-10-15 반영. 관련 코드:
`supabase/migrations/20261015110000_pay_then_approve.sql`, `supabase/functions/esign-pay/`, `index.html`(결제 신청 영역)

## 1. 무엇이 바뀌었나

| 가입자 | 이전 | 지금 |
|---|---|---|
| 무료 체험 | 관리자 승인 후 이용 | **그대로** (관리자 승인 유지) |
| 유료 · 계좌이체 | 관리자 승인 → 조직 생성 → 결제 신청 → 입금 확인 (2번 손이 감) | 승인 대기 화면에서 바로 결제 신청 → 관리자가 **「입금 확인」 한 번** → 구독 시작 + 가입 승인 + 승인 알림톡 |
| 유료 · 카드 | 없음 | 승인 대기 화면에서 카드 결제 → **결제 끝나는 즉시** 구독 시작 + 가입 승인 + 승인 알림톡 |

- 승인 대기 화면의 결제 영역은 **결제 수단이 하나라도 준비됐을 때만** 보입니다
  (계좌 정보 3칸이 모두 입력됐거나, 토스 클라이언트 키가 입력됐을 때).
- 거절 · 정지된 계정은 결제할 수 없습니다.
- 결제한 사람이 조직이 없으면 결제 신청 때 입력한 이름으로 조직이 만들어지고, 그 사람이 소유자가 됩니다.

### 함께 고친 버그
1. **입금 확인 시 요금제가 무료 체험으로 활성화되던 문제** — 결제 신청이 고른 요금제를 저장하지 않아서
   입금 확인 때 조직의 현재 요금제(`free_trial`)로 활성화됐습니다. 이제 결제 행에 요금제 · 주기를 저장합니다.
   (수정 전 결제 기록은 0건이라 실제 피해는 없었습니다.)
2. **다운로드 감사 기록 · 완료 메시지 저장이 서버로 가지 않던 문제** — `sb.rpc(...)` 를 `await` 나 `.then` 없이
   부르면 supabase-js 가 요청을 보내지 않습니다. 감사 기록에 다운로드 항목이 0건이었던 원인입니다.

## 2. 계좌이체 켜기 (바로 가능)

관리자 화면 → 🏢 조직 · 입금 → **결제 설정** 에서 입금 은행 · 계좌번호 · 예금주 3칸을 채우고 저장.

## 3. 카드 결제 켜기 (토스페이먼츠)

### 3-1. 테스트 모드 (계약 전에도 가능)
1. 토스페이먼츠 개발자센터에 가입 · 로그인 → **API 키** 메뉴
2. **「API 개별 연동 키」** 의 테스트 키 두 개를 확인합니다 (결제위젯 연동 키가 아님)
   - 클라이언트 키 `test_ck_…`
   - 시크릿 키 `test_sk_…`
3. **시크릿 키** → Supabase 대시보드 → Edge Functions → **Secrets** → `TOSS_SECRET_KEY` 로 저장
   - 🔴 채팅 · 문서 · 코드 어디에도 붙여 넣지 마세요
4. **클라이언트 키** → 인투오피스 관리자 화면 → 조직 · 입금 → 결제 설정 → 「토스페이먼츠 클라이언트 키」 → 저장
   - 시크릿 키(`_sk_`)를 넣으면 화면이 저장을 막습니다 (모든 회원에게 노출되는 값이기 때문)
5. 승인 대기 계정으로 로그인 → 요금제 선택 → 카드 결제 → 테스트 결제창에서 결제
   → 돌아오면 「결제를 확인하고 있습니다」 → 대시보드 요금제 탭으로 이동하면 성공

테스트 모드 결제는 실제로 돈이 나가지 않습니다(토스페이먼츠 안내 기준 — 직접 확인하지 못했습니다).
테스트로 활성화된 조직 · 결제 기록은 확인 후 정리가 필요합니다.

### 3-2. 실제 결제 (계약 후)
1. 토스페이먼츠 **전자결제 가입 신청 → 심사** (심사 기간 · 수수료 · 필요 서류는 토스페이먼츠 안내를 따르세요. 이 문서에서는 확인하지 못했습니다)
2. 심사 통과 후 받은 **라이브 키** 두 개로 3-1의 3 · 4 단계를 다시 합니다 (`live_sk_…`, `live_ck_…`)
3. 두 키는 **같은 상점 · 같은 모드**여야 합니다. 하나만 바꾸면 결제 승인이 실패합니다.
4. 🔴 라이브 전환 때 함께 고칠 문구 — 지금은 "계좌이체로만 결제"라고 적혀 있습니다
   - 랜딩 요금제 하단 · FAQ (`index.html` 의 `LP_PRICING.foot`, 결제 방법 FAQ)
   - 이용약관 결제 조항 (`LEGAL_DOCS` 의 "결제는 계좌이체 방식으로…")

## 4. 카드 결제가 처리되는 순서 (보안 설계)

1. 브라우저 → `esign_request_payment_v2(method='card')` → 서버가 주문번호 · 금액을 **DB에 먼저 저장**
2. 토스 결제창 → 결제 인증 → 인투오피스로 돌아옴 (`?paymentKey&orderId&amount`)
3. 브라우저 → `esign-pay` 함수
   - 로그인한 사람이 그 주문 조직의 **소유자인지**, 금액이 **DB에 저장된 금액과 같은지** 확인 (주소창 금액 조작 차단)
   - 시크릿 키로 토스 **결제 승인 API** 호출 → `DONE` · 주문번호 · 금액 재확인
   - 구독 활성화 + 승인 대기 소유자 가입 승인 + 다른 대기 결제는 「다른 결제로 대체」 처리
   - 가입 승인 알림톡
4. 승인 API 가 거절하면 주문을 닫습니다 (이 경우 돈은 빠져나가지 않습니다)
5. 결제는 됐는데 활성화가 실패한 드문 경우 → 관리자 화면 「결제 확인 대기」에 **카드 건**으로 남습니다.
   토스페이먼츠 상점관리자에서 결제 완료를 확인한 뒤 「결제 확인」을 누르면 됩니다.

## 5. 아직 하지 않은 것 (다음 단계 후보)
- 카드 **자동 갱신(정기결제 · 빌링키)** — 지금은 한 달 / 1년 단위 1회 결제입니다. 만료 전 재결제 안내가 필요합니다.
- 카드 결제 **취소 · 환불** 버튼 — 지금은 토스페이먼츠 상점관리자에서 취소하고, 인투오피스 쪽 기록은 관리자가 정리해야 합니다.
- 토스 **웹훅** — 브라우저가 돌아오지 못한 경우(창 닫힘 등)를 서버가 스스로 확인하는 장치.
