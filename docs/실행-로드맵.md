## 1. 작업 순서를 정하는 원칙

### 멀티테넌시가 거의 모든 것의 선행 조건입니다

```
알림톡 템플릿  ─┐
요금제 · 과금   ─┼─→ 모두 "조직" 개념이 있어야 성립
업종별 양식 노출 ─┘
```

- 알림톡 템플릿에 `#{조직명}` 변수가 필요 → 조직 개념 선행
- 과금 주체가 개인인지 조직인지 정해져야 결제 설계 가능
- 업종별 양식을 걸러 보여주려면 조직의 업종 정보 필요

### 지금이 가장 싼 시점입니다

현재 데이터는 **문서 8건 · 회원 3명**입니다. 고객이 붙은 뒤 스키마를 바꾸면 실서비스 무중단 마이그레이션이 되고, 난이도가 완전히 달라집니다.

### 알림톡 템플릿 등록은 멀티테넌시 이후

승인된 템플릿은 나중에 변수를 추가할 수 없습니다. 조직명 변수를 빠뜨린 채 심사에 넣으면 4종 전부 재심사 — 약 2주 손실입니다.

### 업종 특화 양식을 먼저 만들면 카카오 심사에도 유리합니다

카카오가 요구한 세 항목 중 **"콘텐츠(판매상품) 확인"** 이 아직 약합니다. 홈페이지에 "학원 · 유학원 · 단체용 전문 양식 35종 제공"이 명시되면 그 자체가 판매상품 증빙이 됩니다. 코드 충돌도 없어 병렬 작업이 가능합니다.

## 4. 권장 진행 순서

```
1주차  ├─ A1 채널 소개글        (전도사님, 오늘)
       ├─ A2 홈택스 업종 추가    (전도사님, 오늘)
       ├─ A3 연락처 확정         (전도사님)
       ├─ B1 홈페이지 마무리     (개발)
       └─ B2 업종 양식 15종      (개발)
              ↓
2주차  ├─ A4 배포 확인 → A5 재심사 신청
       └─ B3 멀티테넌시 스키마 + 마이그레이션
              ↓
3주차  ├─ B4 RLS · 권한 분리
       └─ B5 팀원 초대 UI
              ↓
4주차  ├─ B6 요금제 · 구독 · 사용량
       ├─ B7 입금확인 · 승인 화면
       └─ B9 약관 3종
              ↓
5주차  ├─ A6~A7 솔라피 연동 → pfId
       ├─ B8 알림톡 Edge Function
       ├─ A8 템플릿 4종 심사 신청
       └─ B10 랜딩 페이지
              ↓
6주차  베타 고객 5곳 투입 · 실사용 검증
```

**카카오 심사(A)와 개발(B)은 서로 막지 않습니다.** 심사 대기 시간이 개발 시간으로 흡수되므로, 두 트랙을 동시에 굴리는 것이 가장 빠릅니다.

**단 하나의 순서 제약** — A8(템플릿 심사)은 B3(멀티테넌시)보다 뒤여야 합니다. 조직명 변수 때문입니다.

## 6. 즉시 착수 가능한 작업

D1~D4 결정을 기다리지 않고 지금 바로 진행할 수 있는 것:

- **B2 업종 특화 양식 15종** — 결정과 무관하게 독립적
- **B3 멀티테넌시 스키마 설계** — 요금제 세부값과 무관하게 구조 설계 가능
- **B9 약관 초안** — 보관·삭제 정책, 면책 조항

이 셋을 먼저 진행하면 결정을 기다리는 시간이 낭비되지 않습니다.
