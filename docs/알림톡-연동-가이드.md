# 인투오피스 카카오 알림톡 연동 가이드 (처음부터 끝까지)

카카오톡 채널(`인투오피스` / 검색용 아이디 `intoffice`)을 개설한 시점부터,
서명 요청 알림톡이 실제로 발송되기까지의 전 과정을 순서대로 정리한 문서입니다.

---

## 0. 전체 흐름 한눈에 보기

| 단계 | 하는 일 | 어디서 | 예상 소요 | 결과물 |
|---|---|---|---|---|
| 1 | 카카오톡 채널 개설 | 카카오 비즈니스 | **완료** | 검색용 아이디 `intoffice` |
| 2 | 비즈니스 채널 인증 | 카카오 비즈니스 → 비즈니스 심사 | 영업일 1~3일 | 인증 배지, 알림톡 자격 |
| 3 | 발송대행사 가입 + 발신번호 등록 | 솔라피 등 대행사 콘솔 | 당일~2일 | API Key / Secret, 발신번호 |
| 4 | 발신프로필(채널) 연동 | 대행사 콘솔 | 10분 | **pfId** (발신프로필 키) |
| 5 | 템플릿 등록 → 카카오 심사 | 대행사 콘솔 | 영업일 1~5일 | **templateId** (템플릿 코드) |
| 6 | 코드 연동 | Supabase Edge Function + `index.html` | 반나절 | 자동 발송 |

> 2~5단계는 **인투오피스 코드와 무관한 행정 절차**입니다.
> 이 절차가 끝나서 `pfId`와 `templateId`가 손에 들어와야 6단계 코드가 의미를 갖습니다.
> 반대로 6단계 코드는 미리 만들어 둘 수 있으므로, 심사를 기다리는 동안 병행하는 것이 가장 빠릅니다.

---

## 1. 먼저 잡고 갈 개념 3가지

### (1) 알림톡 ≠ 지금 앱에 있는 "카톡 공유"

현재 `index.html`은 `Kakao.Share.sendDefault()`로 **카카오톡 공유창을 띄우는 방식**입니다.
관리자가 직접 대화방을 골라 보내야 하고, 발송 기록도 남지 않습니다.

알림톡은 **서버가 상대방 전화번호로 곧장 밀어 넣는 방식**입니다.
상대가 채널을 추가하지 않았어도 받고, 발송 성공·실패가 API 응답으로 돌아옵니다.
대량 발송(`esign_create_bulk`)에서 차이가 결정적으로 벌어집니다.

### (2) 알림톡은 카카오와 직접 연결하지 않습니다

카카오는 알림톡 발송 API를 개별 사업자에게 직접 열어주지 않고,
**발송대행사(메시지 대행사)를 경유**하는 구조입니다.
따라서 "카카오 개발자센터에서 알림톡 키를 받는다"는 경로는 존재하지 않습니다.
대행사를 한 곳 골라야 합니다.

| 대행사 | 특징 |
|---|---|
| **솔라피(SOLAPI)** | 개발 문서가 가장 정리되어 있고 콘솔이 쉬움. 소규모 시작에 적합 |
| 알리고 | 단가가 저렴한 편, 문서는 다소 예스러움 |
| 비즈엠 / 비즈고 | 대량 발송·전용 지원 강점 |

이 문서는 **솔라피 기준**으로 작성했습니다. 다른 곳을 써도 절차의 뼈대는 같습니다
(비즈니스 인증 → 발신프로필 → 템플릿 심사 → API 호출).

### (3) 알림톡은 "사전 심사받은 문구"만 나갑니다

문구를 자유롭게 쓸 수 없습니다. 템플릿을 등록해 카카오 심사를 통과해야 하고,
발송 시에는 **승인된 문구와 글자 하나까지 동일**해야 합니다.
바뀔 수 있는 부분만 `#{이름}` 같은 변수로 뚫어 둡니다.
템플릿 초안 4종은 [`docs/알림톡-템플릿-초안.md`](./알림톡-템플릿-초안.md)에 이미 준비되어 있습니다.

## 2. 지금 상태 점검

채널 정보 화면 기준으로 확인된 사항입니다.

- [x] 채널 이름: `인투오피스`
- [x] 검색용 아이디: `intoffice` ← **대행사 연동 시 그대로 입력하는 값**
- [x] 채널 URL: `http://pf.kakao.com/_KvxgxaX`
- [x] 채널 공개: ON
- [x] 검색 허용: ON
- [ ] **비즈니스 인증: 미완료** ← 지금 해야 할 일

채널 공개와 검색 허용이 켜져 있는 것은 알림톡의 전제 조건이라 잘 설정하셨습니다.
남은 것은 왼쪽 메뉴의 **`비즈니스 심사`** 입니다.

---

## 3단계별 진행

### 1단계. 비즈니스 채널 인증 (가장 먼저)

**왜 필요한가** — 일반 채널은 알림톡을 보낼 수 없습니다. 사업자 실체를 확인한
비즈니스 채널만 발송 자격을 갖습니다.

**어디서** — 카카오 비즈니스 파트너센터 → 채널 → **비즈니스 심사**

**준비물**
- 사업자등록번호 / 사업자등록증 사본
- 대표자 또는 담당자 정보
- 업종에 따라 인허가 증빙(교육업이면 학원설립운영등록증 등 요구될 수 있음)

**소요** — 신청 후 영업일 기준 보통 1~3일

> ⚠️ **여기가 첫 번째 관문입니다.**
> 알림톡은 **사업자등록이 되어 있어야만** 쓸 수 있습니다. 개인 명의로는 불가합니다.
> 인투오피스가 별도 사업자등록이 없다면, ① 기존 사업자(인투유학 등) 번호로 인증받고
> 채널을 그 사업자 소속으로 두거나 ② 신규 사업자등록을 먼저 진행해야 합니다.
> 사업자번호와 채널 운영 주체가 다르면 심사에서 반려될 수 있으니, 처음부터 실제
> 서비스를 운영할 사업자로 맞춰 신청하시는 편이 빠릅니다.

---

### 2단계. 발송대행사 가입 + 발신번호 등록

**가입** — 솔라피(solapi.com) 회원가입 후 사업자 정보 등록.

**API Key / Secret 발급** — 콘솔에서 발급합니다.
이 값은 **절대 `index.html`에 넣으면 안 됩니다.** 브라우저 소스는 누구나 볼 수 있어
키가 유출되면 제3자가 사업자 명의로 문자를 발송할 수 있습니다.
반드시 Supabase Secrets에 보관하고 Edge Function에서만 사용합니다(6단계).

**발신번호 등록(발신번호 사전등록제)** — 카카오톡 미설치자에게 **SMS로 대체발송**하려면
법적으로 발신번호를 미리 등록해야 합니다.
- 필요 서류: 통신서비스 이용증명원(휴대폰은 통신사 앱/고객센터, 유선번호는 통신사에서 발급)
- 사업자 명의 번호여야 하며, 개인 명의 번호는 재직/사용 증빙을 추가로 요구합니다.
- 심사 당일~2일

> SMS 대체발송을 안 쓸 계획이면 발신번호 등록을 건너뛸 수 있지만,
> 실무에서는 **카톡 미설치·수신차단 대상자에게 전달이 안 되는 구멍**이 생깁니다.
> 서명 요청은 놓치면 계약 자체가 지연되므로, 대체발송은 켜 두시는 편을 권합니다.

---

### 3단계. 발신프로필(채널) 연동 → `pfId` 받기

솔라피 콘솔 → 카카오 → 채널(발신프로필) 등록에서 아래를 입력합니다.

| 입력 항목 | 넣을 값 |
|---|---|
| 검색용 아이디 | `intoffice` |
| 담당자 휴대폰 번호 | 채널 관리자로 등록된 번호 |
| 카테고리 | 서비스 > 서비스 일반 (채널 설정과 동일하게) |

입력한 번호로 인증번호가 오고, 인증이 끝나면 **`pfId`(발신프로필 키)** 가 발급됩니다.
이 값이 "인투오피스 채널로 보낸다"는 신분증 역할을 합니다.

**자주 막히는 지점**
- 비즈니스 인증이 안 끝난 채널은 여기서 연동 실패합니다 → 1단계 완료 후 재시도
- 입력한 휴대폰 번호가 **채널 관리자 번호와 다르면** 실패합니다
- 검색용 아이디는 `_KvxgxaX`(채널 URL)가 아니라 **`intoffice`** 입니다

---

### 4단계. 템플릿 등록 & 카카오 심사

솔라피 콘솔 → 알림톡 템플릿 → 새 템플릿에서,
[`docs/알림톡-템플릿-초안.md`](./알림톡-템플릿-초안.md)의 4종을 그대로 붙여 넣습니다.

| 템플릿 | 용도 | 발송 시점 |
|---|---|---|
| `인투오피스_서명요청` | 서명 요청 | 문서 생성 직후 |
| `인투오피스_서명리마인드` | 미서명 독촉 | 관리자가 리마인드 버튼 클릭 시 |
| `인투오피스_서명완료` | 완료 통지 | 마지막 서명자 서명 완료 시 |
| `인투오피스_가입승인` | 계정 승인 | 관리자가 회원 승인 시 |

**등록할 때 반드시 지킬 것**
1. 본문에 쓴 변수(`#{이름}`, `#{문서명}`, `#{서명링크}` …)를 **변수 목록에도 똑같이 등록**
2. 버튼은 **웹링크** 타입, 링크에 `#{서명링크}` 변수 사용
3. SMS 대체문구도 함께 등록 (90byte 초과 시 LMS로 과금되니 짧게)
4. 광고성 표현 금지 — "지금 신청", "이벤트", "할인", "무료" 등이 들어가면 반려됩니다

**소요** — 카카오 심사 영업일 1~5일. 통과하면 **`templateId`(템플릿 코드)** 가 나옵니다.

**반려되면** 사유가 함께 옵니다. 대부분 ① 광고성 표현 ② 변수 미등록 ③ 정보성 근거 불명확이며,
해당 문구만 고쳐 재신청하면 됩니다. 재신청 횟수 제한은 없습니다.

> 팁: 4종을 **한꺼번에 신청**하세요. 순차로 하면 심사 대기가 4번 쌓입니다.

---

### 5단계. 코드 연동

여기부터가 개발 작업입니다. 인투오피스는 브라우저에서 Supabase RPC를 직접 호출하는
구조라, **알림톡 발송은 반드시 서버(Edge Function)를 거쳐야 합니다.**

현재 배포된 Edge Function: `esign-auth`, `esign-sign`, `esign-admin`
→ 여기에 **`esign-notify`** 를 추가합니다.

#### 5-1. Supabase Secrets에 키 보관

Supabase 대시보드 → Edge Functions → Secrets에 등록합니다.

```
SOLAPI_API_KEY        = 발급받은 API Key
SOLAPI_API_SECRET     = 발급받은 API Secret
SOLAPI_PFID           = 3단계에서 받은 발신프로필 키
SOLAPI_SENDER         = 등록한 발신번호 (예: 0212345678)
ALIMTALK_TPL_REQUEST  = 서명요청 템플릿 코드
ALIMTALK_TPL_REMIND   = 리마인드 템플릿 코드
ALIMTALK_TPL_DONE     = 서명완료 템플릿 코드
ALIMTALK_TPL_APPROVE  = 가입승인 템플릿 코드
SIGN_BASE_URL         = https://intoedu.github.io/into-office/
```

#### 5-2. 발송 흐름

```
[브라우저]  esign_create_document 성공
     │        (document_id 확보)
     ▼
[브라우저]  POST /functions/v1/esign-notify
     │        { kind: "request", document_id }
     ▼
[Edge Fn]  ① 세션 검증 (본인 문서인지 확인)
           ② DB에서 서명자 이름·연락처·sign_token 조회
           ③ 변수 채워서 솔라피 API 호출
           ④ 발송 결과를 alimtalk_logs 테이블에 기록
     ▼
[솔라피] → [카카오] → 서명자 카카오톡
```

**핵심 설계 원칙**
- 전화번호와 서명 토큰은 **브라우저가 아니라 서버가 DB에서 직접 꺼냅니다.**
  브라우저가 보낸 번호를 그대로 믿으면, 남의 문서 링크를 임의 번호로 보내버릴 수 있습니다.
- 발송 결과는 반드시 로그 테이블에 남깁니다. "보냈는데 안 왔다"는 분쟁이 반드시 생깁니다.
- 실패해도 문서 생성은 성공 처리합니다. 발송 실패로 계약 프로세스가 멈추면 안 됩니다.

#### 5-3. Edge Function 코드 (솔라피 기준 초안)

```ts
// supabase/functions/esign-notify/index.ts
import { createClient } from "https://esm.sh/@supabase/supabase-js@2";

const SOLAPI_URL = "https://api.solapi.com/messages/v4/send-many/detail";

// 솔라피 인증 헤더: HMAC-SHA256(date + salt, apiSecret)
async function authHeader() {
  const apiKey = Deno.env.get("SOLAPI_API_KEY")!;
  const secret = Deno.env.get("SOLAPI_API_SECRET")!;
  const date = new Date().toISOString();
  const salt = crypto.randomUUID().replace(/-/g, "");

  const key = await crypto.subtle.importKey(
    "raw",
    new TextEncoder().encode(secret),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"],
  );
  const sigBuf = await crypto.subtle.sign(
    "HMAC",
    key,
    new TextEncoder().encode(date + salt),
  );
  const signature = [...new Uint8Array(sigBuf)]
    .map((b) => b.toString(16).padStart(2, "0")).join("");

  return `HMAC-SHA256 apiKey=${apiKey}, date=${date}, salt=${salt}, signature=${signature}`;
}

Deno.serve(async (req) => {
  if (req.method !== "POST") return new Response("Method Not Allowed", { status: 405 });

  const { kind, document_id } = await req.json();

  const sb = createClient(
    Deno.env.get("SUPABASE_URL")!,
    Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")!,
  );

  // ① 문서와 서명자 조회 (전화번호·토큰은 서버가 DB에서 직접 확보)
  const { data: doc } = await sb
    .from("esign_documents")
    .select("id, title, deadline, requester_name, esign_signers(name, phone, sign_token, status)")
    .eq("id", document_id)
    .single();

  if (!doc) return Response.json({ ok: false, error: "NOT_FOUND" }, { status: 404 });

  const base = Deno.env.get("SIGN_BASE_URL")!;
  const targets = doc.esign_signers.filter((s) => s.status !== "signed");

  // ② 템플릿 변수 채우기 — 승인된 템플릿의 변수명과 정확히 일치해야 함
  const messages = targets.map((s) => ({
    to: s.phone.replace(/-/g, ""),
    from: Deno.env.get("SOLAPI_SENDER")!,
    kakaoOptions: {
      pfId: Deno.env.get("SOLAPI_PFID")!,
      templateId: Deno.env.get("ALIMTALK_TPL_REQUEST")!,
      variables: {
        "#{이름}": s.name,
        "#{요청자}": doc.requester_name ?? "인투오피스",
        "#{문서명}": doc.title,
        "#{기한}": doc.deadline
          ? new Date(doc.deadline).toLocaleString("ko-KR")
          : "미지정",
        "#{서명링크}": `${base}?s=${s.sign_token}`,
      },
      disableSms: false, // 카톡 미수신 시 SMS 대체발송
    },
  }));

  // ③ 발송
  const res = await fetch(SOLAPI_URL, {
    method: "POST",
    headers: {
      "Authorization": await authHeader(),
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ messages }),
  });
  const result = await res.json();

  // ④ 로그 기록
  await sb.from("alimtalk_logs").insert({
    document_id,
    kind,
    sent_count: messages.length,
    response: result,
  });

  return Response.json({ ok: res.ok, result });
});
```

> ⚠️ 위 코드의 엔드포인트·인증 헤더 형식·`kakaoOptions` 필드명은 솔라피 API 규격 기준으로
> 작성한 초안입니다. **배포 전에 솔라피 최신 API 문서와 대조해 주세요.**
> (작성 환경에서 solapi.com 접속이 차단되어 문서 원문 대조를 하지 못했습니다.)
> 또한 `esign_documents` / `esign_signers` 는 실제 테이블·컬럼명에 맞춰 조정이 필요합니다.

#### 5-4. `index.html` 연동 지점

| 알림톡 | 붙일 위치 | 현재 코드 |
|---|---|---|
| 서명 요청 | 문서 생성 성공 직후 | `esign_create_document` 응답 처리부 |
| 서명 요청(대량) | 대량 생성 성공 직후 | `esign_create_bulk` 응답 처리부 |
| 리마인드 | 리마인드 확정 시 | `confirmRemind()` → `esign_send_reminder` |
| 서명 완료 | 마지막 서명 완료 시 | `esign-sign` Edge Function 내부 |
| 가입 승인 | 회원 승인 시 | `esign_set_member_status` (status → active) |

호출 예시:

```js
async function sendAlimtalk(kind, documentId) {
  try {
    const res = await fetch(SB_URL + '/functions/v1/esign-notify', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ kind, document_id: documentId })
    });
    const r = await res.json();
    if (!r.ok) showToast('알림톡 발송에 실패했습니다. 링크를 직접 전달해 주세요.');
  } catch (e) {
    // 발송 실패가 문서 생성 자체를 막지 않도록 조용히 처리
    console.error(e);
  }
}
```

기존 "카톡 공유" 버튼은 **지우지 말고 남겨 두세요.** 알림톡 실패 시의 대체 수단이자,
심사 대기 기간에도 서비스를 계속 굴릴 수 있는 경로입니다.

## 4. 비용

- 월 기본료·API 사용료: 없음 (건당 과금)
- 알림톡 단가: 검색 기준 월 1~9,999건 구간에서 **건당 약 13원**, 발송량이 늘면 자동 할인
- SMS 대체발송: 별도 단가(SMS는 알림톡보다 비쌈, LMS는 더 비쌈)

> 단가는 대행사·시점에 따라 달라집니다. 위 수치는 검색으로 확인한 값이며,
> 계약 전 솔라피 가격 정책 페이지에서 직접 확인하시기 바랍니다.
> 월 500건 발송을 가정하면 알림톡 비용은 대략 월 7천원 수준으로, 부담이 큰 항목은 아닙니다.

## 5. 놓치기 쉬운 위험 요소

### (1) 서명 링크가 메시지에 그대로 담깁니다
알림톡 본문에 `?s=토큰` 링크가 들어갑니다. 문자를 전달받은 제3자도 열 수 있습니다.
- **대응** — 문서에 접근 암호를 설정하고, **암호는 알림톡이 아닌 별도 경로(전화 등)로 전달**하세요.
  링크와 암호가 같은 메시지에 있으면 보안 장치가 무의미해집니다.
- 서명 기한을 짧게 잡아 만료된 링크가 떠돌지 않게 하세요.

### (2) 템플릿 문구와 1글자라도 다르면 발송 실패
승인된 문구를 코드에 하드코딩해 두고, 템플릿 수정 시 **양쪽을 함께 고쳐야** 합니다.
템플릿만 수정하고 코드를 안 고치면 전량 발송 실패합니다.

### (3) 전화번호 형식
`010-1234-5678` 형태로 저장되지만 API는 하이픈 없는 `01012345678`을 요구합니다.
위 코드의 `replace(/-/g, "")` 처리가 그 부분입니다.
대량 명단 업로드 시 `010 1234 5678`, `+82 10-...` 같은 변형이 섞여 들어오므로
정규화 로직을 한 곳에 모아 두는 편이 안전합니다.

### (4) 정보성 메시지의 경계
서명 요청·완료 통지는 **수신자의 행동에 따른 정보성 안내**라 알림톡 자격이 있습니다.
하지만 여기에 "인투오피스의 새 기능을 확인해 보세요" 같은 홍보 한 줄이 붙는 순간
광고성으로 분류되어 채널 제재 대상이 됩니다. 템플릿을 절대 임의로 바꾸지 마세요.

## 6. 체크리스트

```
[ ] 1. 사업자등록증 준비 (인투오피스를 운영할 사업자 확정)
[ ] 2. 카카오 비즈니스 → 비즈니스 심사 신청          → 1~3영업일
[ ] 3. 비즈니스 인증 완료 확인
[ ] 4. 솔라피 가입 + 사업자 정보 등록
[ ] 5. 발신번호 등록 (통신서비스 이용증명원)          → 당일~2일
[ ] 6. API Key / Secret 발급 → 안전한 곳에 보관
[ ] 7. 발신프로필 연동 (검색용 아이디 intoffice)     → pfId 확보
[ ] 8. 템플릿 4종 일괄 등록 → 카카오 심사            → 1~5영업일
[ ] 9. templateId 4개 확보
[ ] 10. Supabase Secrets 등록
[ ] 11. esign-notify Edge Function 배포
[ ] 12. index.html 연동 (문서 생성 / 리마인드 / 완료 / 가입승인)
[ ] 13. 본인 번호로 테스트 발송 → 링크 클릭 → 서명 완주 확인
[ ] 14. 발송 로그 테이블 확인
```

**심사 대기 시간이 전체 일정을 좌우합니다.** 1단계와 4단계를 최대한 빨리 걸어두고,
기다리는 동안 11~12번 코드 작업을 병행하는 것이 가장 빠른 경로입니다.
